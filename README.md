# HTC Image Upload Workbench

**htc传图工具台 / HTC 图片上传工作台**

公司内部图片上传工具，包含 Windows Electron 客户端、React 网页界面与 Cloudflare Workers 服务端。源码版本 **1.5.0**。

## 功能

- 默认 alpha / beta / gamma / delta 四账号卡片，显示在线设备及上传占用，点击直接进入；管理员单独使用密码入口。普通运营入口由显式开关控制，仅限四个启用的员工账号，不包含管理员。
- 按员工账号归档和恢复本机未完成队列，切换账号不会清空其他账号的任务；管理员账号管理、业务组隔离和权限分配保留。
- 选择或拖入图片/文件夹，保留相对目录；支持 JPG、PNG、WebP，单图最大 50 MB。
- 公司共享 20 路上传，按正在上传的设备动态分配；一台最多 20 路、两台各 10 路、三台 7/7/6 路、四台各 5 路。同一员工账号的不同设备分别计入，登录空闲设备不占额度。
- 暂停、恢复、仅重试失败及本地任务检查点。
- 桌面端支持连续添加图片，可并入当前任务或新建排队任务。大目录按每组最多 20,000 张依次处理，同一商品目录的套图一起进入同一组。
- 任务总览显示原始路径、整体进度和预计完成时间，支持重命名上架任务。
- Excel/CSV 支持逐张明细或每产品一行。按产品导出时，A 列保留直接上级文件夹名，图片按文件名自然排序。新版服务每次最多返回 4,000 条链接，保存前会核对快照完整性。
- 图片保留 7 天，公开地址支持 GET/HEAD。
- 1.1.1 起使用安装版自动更新：启动与每小时检查、后台下载、空闲时点击重启安装；普通退出不强制更新。

上传前压缩的底层模块已有测试，但“手动压缩对比、整批选择版本”的完整交互尚未接入，不属于当前可用功能。

## 结构

| 路径 | 用途 |
| --- | --- |
| `src/` | React 界面、上传队列、导出和前端测试 |
| `electron/` | 窗口、受限 IPC、原生传输和本地持久化 |
| `server/` | Worker API、鉴权、D1 数据表、R2 签名和后端测试 |
| `scripts/` | 图标生成、资源打包和内部发布校验 |
| `assets/`、`public/` | 图标和静态素材 |
| `docs/` | 部署说明与历史实施方案 |

D1 保存用户、权限、任务、元数据和上传租约，R2 保存图片。客户端获得短期预签名 URL 后直传 R2，服务端确认对象后生成公开图片地址。

## 开发与验证

建议使用 Node.js 24 和 npm；Windows 客户端在 Windows 上打包。

```powershell
npm ci
Copy-Item .dev.vars.example .dev.vars
npx wrangler types
npm run build:web
npm run build:server
npm run typecheck
npx tsc --noEmit -p tsconfig.server.json
npm test
```

前端开发：`npm run dev`。Electron 启动前先构建网页，再运行 `npm run desktop`。

本地联调可运行 `npx wrangler dev` 并访问其网页/API。Electron 的默认连接地址在 `server.json`，仍指向现有部署，注意区分本地和生产数据。

1.1.3 本地完整回归 **292 项通过（33 个测试文件）**，包括账号密码、表单弹窗、会话切换、并发、上传中断、恢复、独立批次和导出。

## Windows 打包

```powershell
npm run build:web
npm run pack:win -- --config.directories.output=release
```

EXE 可直接分发，员工电脑无需安装 Node.js；使用时需要联网并登录。

运行 `node scripts/verify-release.cjs <构建目录> [交付目录]` 可校验安装包、更新清单与应用标识。指定构建目录作为交付目录时，校验报告直接保存在安装包旁。

## 部署与凭据

见 [部署维护](docs/部署维护.md)。仓库保留当前资源绑定标识和公开地址；部署到其他账号前需更新 `wrangler.jsonc`、`server.json` 与构建脚本中的对应域名。

仓库不包含生产 Token、R2 密钥、员工密码、会话令牌、业务图片或安装包。测试里的密码与密钥是测试夹具，不是生产账号配置。

务必保留生产 `CONFIG_KEY`；R2 连接凭据由其加密，不能用示例值覆盖。员工只需 EXE 与本人账号，无需长期 R2 凭据。

本项目按私有公司仓库维护，当前未声明开源许可证。

1.0.9 为 Windows 客户端热修复：IPC 来源校验按真实本地文件路径比较，兼容短路径 ~ 和方括号的不同 URL 编码。当时服务端为 1.0.8。

1.1.0 更新套图导出规则：每个完整目录单独一行，首列显示直接上级文件夹名；支持任意图片文件名并自然排序，不再根据数字编号预留空列。

版本命名按十进位递增：补丁位与次版本位均为 0–9，例如 1.0.9 → 1.1.0，1.9.9 → 2.0.0；更新时同步 package.json、锁文件、服务端健康版本和 EXE 文件名。

自动更新的存储、发布权限、分块发布与验收方式见 [自动更新维护](docs/自动更新维护.md)。
